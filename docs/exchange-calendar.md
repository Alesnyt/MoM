# Календарь Exchange

Первая версия предназначена для собственного корпоративного Exchange с доступной службой EWS и входом NTLM либо Basic через HTTPS. Сервер выбирает администратор. После успешного входа через LDAP собственный календарь подключается автоматически в фоне; ошибка Exchange не препятствует входу в MoM. Microsoft 365 / OAuth, MFA через браузер, autodiscover, делегированные и общие календари пока не реализованы.

## Настройка и проверка

1. Откройте **Админка → Exchange**, включите календарь и укажите конечный адрес `https://mail.company.ru/EWS/Exchange.asmx`. Адрес веб-почты вида `https://mail.company.ru/owa` автоматически приводится к пути EWS на том же сервере; если EWS опубликован отдельно, нужен его фактический адрес.
2. Оставьте NTLM для доменной учётной записи. Basic выбирайте только если он разрешён для вашей службы EWS. Сохраните настройки.
3. Для LDAP-профиля выйдите из MoM и войдите снова: календарь подключится тем же паролем автоматически. Справа показываются ход подключения и возможная ошибка. Выбрать другую учётную запись нельзя. Локальный тестовый профиль подключается вручную: введите логин (`DOMAIN\login` либо UPN) и пароль Exchange; целевой ящик всё равно закреплён за email профиля MoM.
4. Дождитесь подключения; для ручного режима нажмите **Подключить календарь**. Вход проверяется чтением календаря. Блок **Ваш рабочий календарь** по умолчанию показывает сегодняшний день. Можно выбрать дату и период (день или неделю), перейти стрелками на предыдущий/следующий период и обновить события. Кнопки **Вчера** и **Сегодня** открывают соответствующий день, в том числе после просмотра недели. Отменённые встречи выбрать нельзя.
5. Выберите встречу и проверьте повестку, время, приглашённых и переговорки. Затем загрузите запись или импортируйте транскрипт. При ошибке получения деталей привязка не создаётся; можно повторить выбор или продолжить без календаря.

LDAP-вход запускает подключение только если Exchange включён. Уже открытая сессия не содержит пароль от прошлого входа: после включения интеграции потребуется войти заново. Изменение адреса/режима входа и выключение календаря отключают текущие подключения. Календарь необязателен: загрузка записи без выбора события работает как прежде.

## Как используется приглашение

Название подставляется в поле встречи, его можно поправить перед загрузкой. Выбранное название сохраняется при сборке протокола. Повестка и место дополняют поиск релевантных терминов в корпоративном глоссарии; справочный контекст ограничен по размеру. Добавочных моделей, векторизации и фонового обхода календарей нет.

Приглашённые и организатор доступны как отдельные подсказки при ручном назначении спикеров. Ресурсы и переговорки исключены из этих подсказок. Приглашение не доказывает фактическое участие; его повестка не считается принятым решением. Получатели протокола по приглашению автоматически не назначаются.

## Данные и нагрузка

- Только EWS `FindItem` в календаре основного почтового ящика, закреплённого за профилем и `GetItem` выбранного календарного события. Письма, вложения и контакты не запрашиваются; операций изменения/отправки нет.
- `CalendarView` возвращает отдельные вхождения повторяющихся встреч. Запрашиваются до 200 событий за период не более 31 дня; при усечении интерфейс предлагает сократить период. Даты передаются в UTC, отображаются во времени браузера.
- Список содержит только краткие поля; тело приглашения и участников запрашиваем по нажатию. Кэш списка — 5 минут, кнопка «Обновить» обходит его. Не более четырёх одновременных запросов EWS, одного запроса на подключение. Повторять вход с паролем автоматически не пытаемся.
- Ответ EWS ограничен 2 МиБ, повестка — 8000 символов, списки участников — 100 на категорию. Контекст для протокола — до 5000 UTF-8 байт, дополнительно ограничивается общим окном модели. При большом приглашении часть контекста сокращается.
- Для LDAP-профиля сервер находит единственный объект AD по email профиля в областях **входа**, читает `userPrincipalName`, `mail`, `proxyAddresses`; верхнерегистровый `SMTP:` задаёт основной адрес. При неоднозначности подключение отклоняется. Кэш/области поиска спикеров не участвуют. В EWS явно задаётся этот ящик, передать другой из браузера нельзя. Служебная учётка LDAP используется только для чтения атрибутов AD и не отправляется в Exchange.
- Пароль находится только в памяти процесса в клиенте подключения. После успешной LDAP-аутентификации он передаётся фоновому подключению своей сессии; до четырёх таких подключений одновременно, без неограниченной очереди. Он не попадает в БД, `.env`, аудит или встречу. Подключение привязано к сессии MoM, живёт не дольше её 12 часов; очищается при отключении, выходе, истечении или отзыве сессии, смене настроек и остановке процесса. Не более 128 подключений; при заполнении удаляется давно не использовавшееся.
- Выбранное приглашение сохраняется со встречей как снимок; в дальнейшем оно не обновляется из Exchange автоматически. Остальные события на диск не записываются. Повестка и приглашённые могут содержать служебную информацию: выбранные данные передаются настроенной модели протокола как часть контекста.
- Развёртывание однопроцессное, как и остальная очередь MoM. Пользовательский доступ к рабочему MoM должен быть по HTTPS; локальный тест слушает только loopback.

## Если не подключается

- **401/403:** проверить домен/логин, пароль и разрешение EWS для пользователя. Работа OWA/Outlook сама по себе не гарантирует этот способ входа в EWS. OAuth/MFA пока не поддерживаются; отключать требования корпоративной аутентификации не нужно.
- **404:** неверный путь либо EWS не опубликован на этом адресе.
- **Перенаправление/HTML вместо XML:** нужен конечный адрес EWS, а не страница входа веб-почты. Перенаправления с учётными данными запрещены.
- **Сертификат:** установите корпоративный CA в доверенный bundle сервера MoM (`SSL_CERT_FILE`); проверку TLS не отключаем.
- **Долгий ответ:** тайм-аут соединения 5 секунд, чтения 15 секунд, дополнительно проверяется бюджет 30 секунд при поступлении порций ответа. Можно отменить подключение; его поздний результат не восстанавливает сессию. Для перегруженного сервера обновите список позже.
- **После перезапуска/выхода:** для LDAP войти в MoM заново, для локального тестового профиля подключить календарь вручную. При недоступности AD или отсутствии UPN/основного SMTP-адреса подключение не подменяет учётную запись.

## Проверки

Автотесты проверяют SOAP-контракт, выбранные поля, повторы событий через CalendarView, HTTPS без редиректов, ограничение XML, разделение сессий и двух LDAP-пользователей, отсутствие подключения при неверном пароле, отзыв сессии, отмену, очистку пароля, кэш, перенос контекста в обработку и сохранение названия. Интерфейс проверяется на выбор/смену события, отмену входа, истёкшую сессию и ручное назначение приглашённых. Эти проверки используют имитированный EWS; совместимость с конкретным сервером подтверждается отдельным входом пользователя.
