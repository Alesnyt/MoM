# Корпоративный контекст

Администратор один раз подключает каталог и загружает словарь в **Админка → Контекст**. Пользователь загружает запись как обычно: отдельное описание встречи не требуется.

## Настройка

1. Настройте AD в разделе «Каталог» и выберите области поиска сотрудников.
2. В разделе «Контекст» выберите поля и разрешённые почтовые домены, сохраните правила и нажмите «Синхронизировать AD». По умолчанию загружаются только ФИО (`displayName` / `cn`), email (настроенный атрибут с резервным `mail`), должность (`title`), подразделение (`department`) и фамилия (`sn`). Последние три поля можно отключить. Другие атрибуты AD не запрашиваются. Без подразделения не будет приоритета контекста по отделу, без фамилии — подбора по уникальной фамилии. Автоматическое обновление включено по умолчанию на **03:00 по Москве (UTC+3)**. Выберите другое время в поле «Время запуска» и нажмите «Сохранить время»; ближайший запуск отображается рядом. Часовой пояс сервера или браузера не меняет расписание. Новое время применяется с ближайшего будущего запуска, ручное обновление не сдвигает ежедневное расписание. После простоя пропущенный запуск текущего дня выполняется при старте; после ошибки повторная попытка выполняется через 15 минут. Планировщик проверяет очередь раз в минуту. Изменение подключения, областей, доменов или полей делает старый снимок недоступным для новых задач и поиска спикеров до успешной синхронизации.
3. Загрузите `.xlsx` или `.csv` со столбцами ниже. Кнопка «Скачать образец CSV» создаёт готовый пример.

| Столбец | Назначение |
| --- | --- |
| Термин / term | Обязательное правильное написание: `TrueConf` |
| Варианты / aliases | Явные варианты через `\|`: `труконф\|тру конф` |
| Описание / description | Краткое объяснение для протокола |
| Подразделение / department | Приоритет для сотрудников этого подразделения; пустое поле — общий термин |

Подразделение влияет на приоритет подбора, а не на права доступа. Заполняйте только однозначные варианты: если указать обычное слово как вариант названия системы, оно будет заменяться и при обычном употреблении. При конфликте вариантов между разными терминами автоматическая замена не выполняется.

Импорт заменяет предыдущий словарь целиком, сохраняя сотрудников AD отдельно. Ошибочный файл не меняет действующий словарь. Ограничения: 2 МБ, 5000 строк, 20 вариантов на термин; длина термина/варианта/подразделения — 120 символов, описания — 500. CSV поддерживает UTF-8 и Windows-1251, разделители запятая, точка с запятой и табуляция. Excel читает активный лист; формулы нужно заменить значениями. Старый формат `.xls` не поддерживается.

## Ограничения AD и быстрый поиск спикеров

В «Контекст → Выбрать домены AD и OU» доступен тот же выбор областей, что в разделе «Каталог». Выбранная OU включает вложенные подразделения; несколько областей объединяются. Чтобы исключить подрядчиков внутри общей OU, выбирайте дочерние OU сотрудников.

«Разрешённые почтовые домены» — дополнительное ограничение синхронизации: точное совпадение домена email, без поддоменов и масок. Пустое поле разрешает любой домен. Перечисляйте через запятую, пробел или с новой строки; `@company.ru` и `company.ru` равнозначны. Между доменами действует «или», между доменом и выбранными OU — «и». При заданном списке запись без email не загружается. Фильтрация выполняется в LDAP-запросе и повторно перед сохранением. Правила полей/почтовых доменов хранятся в `app_settings.ldap_sync_policy`; они не ограничивают вход в MoM или отдельный поиск для создания пользователей в админке.

Подсказки спикеров используют последний успешно синхронизированный справочник в SQLite. Поиск по части ФИО или email не обращается к AD, не зависит от его задержек и продолжает работать после ошибки обновления. Регистр и «е/ё» не различаются; слова можно вводить в любом порядке. Локальные профили MoM остаются доступны отдельно. При отсутствии актуальной копии интерфейс объясняет, что требуется синхронизация, и разрешает ручной ввод. Выключение контекста для распознавания не выключает поиск спикеров.

Индекс поиска переиспользуется в памяти и обновляется после изменения снимка другим процессом. Первое обращение после обновления строит индекс; последующие не декодируют весь справочник заново. При изменении области или правил старая копия сразу исключается из поиска. Готовые встречи и уже назначенные имена/должности не переписываются.

## Автоматический подбор

Для новой задачи загружается снимок словаря. Подразделение определяется по email загрузившего запись сотрудника в AD. Перед локальным Whisper выбираются термины по заголовку записи, подразделению и общему словарю; подсказки ограничены 500 байтами UTF-8.

После распознавания список уточняется по тексту: точное упоминание термина или его варианта имеет больший приоритет. Для сотрудников учитываются полное имя и уникальная фамилия; однофамильцев по одной фамилии система не выбирает. Сотрудники из одного отдела без упоминания не заполняют список подсказок. Выбирается до 30 записей; языковой модели передаётся только эта подборка в пределах бюджета её контекстного окна.

Для всех движков распознавания нормализуются только точные, однозначные варианты из загруженного словаря. Исходные реплики сохраняются и доступны по ссылке «До корпоративного словаря». Таймкоды и спикеры сохраняются. GigaAM в этой версии использует эту нормализацию после распознавания; его акустический декодер не изменён. Облачному ASR словарь не передаётся; выбранные пояснения используются при последующей сборке протокола настроенной LLM.

Готовые встречи не переписываются после импорта. При продолжении сборки протокола подбор контекста выполняется по актуальному снимку, при этом сохранённый транскрипт заново не нормализуется. Номер ревизии и использованная подборка сохраняются с результатом. Общий переключатель отключает применение контекста к последующей обработке; фоновая синхронизация AD управляется отдельно.

## Эксплуатация

Снимок хранится в существующей SQLite-базе MoM и попадает в её резервную копию. Дополнительный сервис, GPU или векторная база не нужны. Подбор выполняется локально, без сетевого поиска на каждую запись. Синхронизация AD использует существующие настройки соединения и области поиска, постраничную загрузку, лимит 50 000 сотрудников и минутный срок выполнения. Частичный результат не заменяет последний полный снимок. Блокировка в базе координирует ручную и фоновую синхронизацию между процессами, а после аварийного завершения истекает через две минуты. Изменения настроек, импорт и успешные синхронизации записываются в журнал.

Проверки поведения AD выполнены на тестовом соединении: страницы, ограничения областей, неполные ответы, смена настроек, одновременные запуски. Связь с рабочим корпоративным AD проверяется после установки в контуре.

Замеры распознавания и стоимости подбора: [CPU benchmark](../benchmarks/README.md).
