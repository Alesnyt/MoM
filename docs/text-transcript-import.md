# Встреча из готового транскрипта

В форме новой встречи выберите **Готовый транскрипт**, вставьте текст или загрузите `.txt`, `.md`, `.srt`, `.vtt` в UTF-8. Нажмите **Импортировать транскрипт**, проверьте имена и распределение реплик, затем **Собрать протокол**. Импорт работает без настроенного LLM; ключ нужен только для сборки протокола. Аудио, ffmpeg, ASR и диаризация при этом не вызываются.

## Формат и ограничения

```text
[00:05] Анна Иванова: Обсудим план.
Иван Петров: Подготовлю документ к пятнице.
Анна Иванова: Спасибо.
Продолжение той же реплики на следующей строке.
```

- Поддерживаются `Имя: текст`, `[MM:SS] Имя: текст`, `HH:MM:SS.mmm Имя: текст`, дробные секунды через точку или запятую; Markdown-метки `**Имя:**` и `**Имя**:`.
- Одинаковые имена с разным регистром или лишними пробелами относятся к одному спикеру. Написание первого имени сохраняется. Разные псевдонимы автоматически не объединяются: это можно сделать через назначение реплик в интерфейсе.
- Строка без метки продолжает предыдущую реплику; начальный текст без имени получает спикера «Неясно». Markdown читается как текст, HTML не исполняется.
- В SRT/VTT поддерживаются стандартные блоки таймкодов, необязательные номера/идентификаторы, имя в начале текста или VTT `<v Имя>…</v>`. В одном блоке должен быть один говорящий. VTT NOTE/STYLE/REGION пропускаются. Это импорт реплик, а не проигрыватель всех расширений субтитров.
- Без таймкода время остаётся `null`, в интерфейсе и экспорте не подставляется `00:00`. Указанное время сохраняется в сегментах; длительность аудио не выдумывается.
- Лимит: 1 МиБ UTF-8, 10 000 реплик, 200 спикеров, имя до 80 символов, название до 200. Общий HTTP-запрос ограничен 1 МиБ + 64 КиБ до разбора multipart, включая запросы без Content-Length. Бинарные данные и неверная кодировка отклоняются.

## API и хранение

Новый `POST /api/meetings/transcript` принимает авторизованную пользовательскую сессию и form-data: **либо** `text`, **либо** `file`, плюс необязательный `title`. Для вставки также принимается `application/x-www-form-urlencoded`. Ответ — обычный объект встречи со статусом `review`, списками `speakers` и `segments`, `transcript` и `source_type: "text"`. Ошибки: 400 — неверный формат, 401 — нет сессии, 413 — превышен размер, 507 — мало диска. Доступ к чужим встречам возвращает 404.

Далее используется существующий `POST /api/meetings/{id}/protocol`, редактирование спикеров, экспорт и архивный лимит пользователя. Повторная сборка и перезапуск текстовой встречи сохраняют транскрипт и ручные имена. Аудио API `POST /api/meetings` не меняется.

Схема SQLite не меняется: источник хранится внутри существующего `segments_json`. Создание строки и сохранение транскрипта атомарны: воркер никогда не видит импорт как аудиозадачу. Исходный текстовый файл отдельно на диск не записывается. Новых зависимостей, переменных окружения, томов, портов и изменений корпоративного развёртывания нет.

## Ручное обновление после разрешённого merge

1. Дождаться зелёного CI и явного разрешения на merge. До этого использовать ветку PR только на тестовой установке с отдельной копией данных.
2. На сервере прекратить новые загрузки, дождаться завершения текущих задач. Записать `git rev-parse HEAD`, сохранить текущий Docker-образ или Python-окружение.
3. Сделать резервную копию: `docker compose exec mom python -m backend.backup` или `.venv/bin/python -m backend.backup`. Сохранить `.env` отдельно в защищённом месте.
4. После merge: `git fetch origin`, `git checkout main`, `git pull --ff-only`.
5. Docker: `docker compose build`, затем `docker compose up -d --no-deps mom`. Обычная установка: `./update.sh --no-pull`, проверить `mom.service`; при ручном запуске остановить старый процесс и выполнить `./start.sh`.
6. Проверить `/api/health`, вход, старые встречи и протоколы. Импортировать пример выше вставкой и файлом; после обновления страницы должны сохраниться имена и пустые таймкоды. Переименовать спикера, собрать протокол, проверить повторную сборку, экспорт и изоляцию второго пользователя. Отдельно проверить короткую аудиозапись до `review` и `done`.
7. Просмотреть журнал приложения и свободный диск. Не выполнять `down -v` и не удалять тома.

Откат: остановить приложение, сохранить текущее состояние, вернуть записанный коммит и прежний образ/окружение. Обратная миграция SQLite не нужна. Новые текстовые встречи остаются в БД, но старая версия не знает их источник: **не использовать её кнопки повторной обработки/перезапуска для импортированных встреч**. Не восстанавливать старую БД поверх новых данных без отдельного решения — это потеряет новые встречи.
