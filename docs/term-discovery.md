# Фоновое пополнение сокращений и названий систем

**Админка → Контекст → Предложения терминов.** Поиск включён по умолчанию, первый запуск — в ближайшие **03:30 по Москве (UTC+3)** после обновления. Время, включение и лимит порций меняются в панели. Есть ручной запуск и остановка.

Анализ использует уже настроенную модель протоколов и её подключение. Это дополнительные обращения к этой модели: до 100 порций по 6000 символов за запуск по умолчанию. Можно поставить лимит 1–500. GPU, новые модели и повторное распознавание аудио не нужны. Наличие ключа и доступность модели необходимы; ошибка видна в панели, прогресс не теряется.

## Как собираются предложения

- Обрабатываются новые или изменившиеся исходные реплики встреч в состоянии «разметка» или «готово». При первом запуске также разбираются уже сохранённые встречи. Записи, удалённые из архива до анализа, не обрабатываются.
- Для изменённых корпоративным словарём реплик берётся `context_original_text`. Переименование спикеров без изменения исходного текста не вызывает новых запросов к модели.
- Модель выделяет предполагаемые названия систем, сокращения и варианты произношения, включая неизвестные глоссариям. Она не задаёт окончательное написание. Проверяется, что каждое предложение дословно присутствует в указанной реплике. Выдуманные термины, отсутствующие в ней, не сохраняются.
- Уже известные точные написания/варианты исключаются по действующему контексту. Приблизительная фонетическая группировка объединяет варианты для просмотра, но не разрешает замену. Ошибочные группировки возможны — администратор выбирает варианты отдельно.
- Варианты упорядочиваются по числу разных встреч. Для каждого сохраняется до трёх примеров на встречу, в панели показываются три последних примера. Не больше 20 групп на страницу и 20 вариантов группы за раз; после рассмотрения первых появляются оставшиеся.
- Отклонение запоминается для точного нормализованного варианта. Отложенное предложение возвращается через семь дней. После удаления встречи удаляются её фрагменты и связанные примеры; счётчик отражает оставшийся архив. Само решение по термину сохраняется.

## Подтверждение и отмена

Выберите варианты, укажите правильное написание и при необходимости пояснение. В поле написания доступен поиск существующих терминов. Новое написание можно ввести вручную.

По умолчанию подтверждённые варианты участвуют **только в подборе контекста**. Для автоматического исправления транскрипта нужно отдельно включить флажок замены. Если заполнено подразделение, замена применяется только к встречам владельцев с соответствующим подразделением из AD (нормализованное точное совпадение). При неизвестном подразделении владельца такая замена не применяется. Поле не ограничивает права доступа к справочнику.

Создаётся отдельный управляемый глоссарий **«Сокращения и названия систем»**. Подтверждение того же названия/подразделения добавляет варианты в ту же запись. До 5000 терминов, до 20 вариантов на термин, общий лимит всех глоссариев — 100 000. Бизнес- и дата-глоссарии не перезаписываются. Excel/CSV нельзя импортировать поверх управляемого справочника; остальные источники импортируются как раньше.

На вкладке «Подтверждённые» можно отозвать выбранный вариант и пересмотреть его. Публикуется новая версия справочника; уже начатые задачи используют свою версию контекста, готовые протоколы автоматически не переписываются. Конфликт с другими терминами блокирует автоматическую замену по существующим правилам контекста. Справочник целиком можно отключить в списке глоссариев.

## Нагрузка, сбои и доступ

Работает один фоновый запрос на установку, с арендой задания в SQLite. После сбоя процесс продолжит с сохранённой порции. Публикация решения администратора и обновление справочника происходят одной транзакцией; повторное или конкурентное решение по устаревшей карточке отклоняется.

Между порциями — пауза пять секунд. Если появляются встречи в очереди или обработке, новые обращения откладываются; текущий клиентский запрос отменяется при следующей проверке (примерно раз в секунду), порция остаётся непроверенной. Сервер модели может закончить уже полученный запрос даже после отмены клиента. Тайм-аут обращения — 45 секунд, автоматических сетевых повторов нет. Для провайдеров без JSON-режима допускается один повтор без него. Лимит учитывает начатые попытки порций, включая отменённые.

Остановка в интерфейсе сохраняет прогресс и игнорирует поздний ответ модели. Ошибка модели завершает текущий прогон: повтор — вручную либо в следующий ежедневный запуск. Необработанные порции переносятся. Очередь до 10 000 неподтверждённых/отложенных вариантов; при заполнении нужно рассмотреть предложения и повторить запуск.

Все маршруты, примеры и аудиофрагменты доступны только администратору. При прослушивании по запросу готовится до 60 секунд от начала реплики (с двухсекундным запасом), а не от точного времени отдельного слова. Для текстовых импортов и удалённого аудио кнопка недоступна. Фрагменты не сохраняются отдельными файлами. Решения и настройки записываются в журнал, таблицы входят в штатную резервную копию `mom.db`.

Текущая версия не удаляет слова-паразиты и не обучает веса ASR-модели. Это очередь терминологических предложений с подтверждением. Качество обнаружения зависит от выбранной модели протоколов; проверять его нужно на корпоративных примерах. [Локальные проверки и замеры](../benchmarks/term-discovery.md).
