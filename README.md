# MoM — саммари, поручения и протоколы встреч

[![CI](https://github.com/Alesnyt/MoM/actions/workflows/check.yml/badge.svg)](https://github.com/Alesnyt/MoM/actions/workflows/check.yml)

**MoM (Minutes of Meeting)** — self-hosted веб-сервис, который превращает аудио- и видеозаписи встреч в редактируемый транскрипт, краткое содержание, принятые решения, список поручений и структурированный протокол. Подходит для личной установки и развёртывания на сервере внутри организации.

**Основной сценарий:** загрузить запись → дождаться распознавания → проверить и при необходимости переименовать спикеров → запустить проверку имён и сборку протокола → сохранить результат или отправить его по почте.

## Возможности

- **Записи:** `webm`, `mkv`, `mp4`, `mp3`, `wav`, `m4a`, `ogg`; ограничение размера файла и проверка свободного места на диске.
- **Распознавание речи (ASR):** локальные **faster-whisper** (по умолчанию) и **Сбер GigaAM Multilingual**; по настройкам возможен облачный ASR через совместимый API.
- **Спикеры:** опциональная диаризация через **pyannote.audio**; ручное переименование и переназначение реплик на этапе проверки транскрипта.
- **Протокол через LLM:** **Qwen, OpenAI, Gemini, OpenRouter** или свой **OpenAI-совместимый API**; извлекаются саммари, ключевые тезисы, решения, поручения с исполнителями и сроками, повестка и итоги.
- **Многопользовательский доступ:** локальные учётные записи либо **LDAP/LDAPS**, раздельные архивы встреч, сессии и журнал аудита.
- **Эксплуатация:** очередь с настраиваемым параллелизмом, повтор обработки, остановка/перезапуск, уведомления через SMTP, резервное копирование и запуск в Docker или как Linux-сервис.
- **Интерфейс:** React + TypeScript, административная панель, темы `classic` и `t2`, выгрузка Markdown и подготовка письма с протоколом.

## Архитектура и поток обработки

```text
React / TypeScript
       |
    FastAPI  ────────── SQLite (пользователи, встречи, сессии, аудит)
       |                             + data/ (записи, модели, экспорты)
    Очередь задач
       |
    ffmpeg → Whisper / GigaAM / облачный ASR
       |                     |
       └──── pyannote (опционально)
                     |
               Проверка спикеров
                     |
              LLM: саммари / MoM
                     |
         Архив / Markdown / SMTP
```

Основные части кода: `frontend/src/` — интерфейс; `backend/main.py` — HTTP API и доступ; `backend/worker.py` и `backend/pipeline.py` — очередь и стадии обработки; `backend/local_asr.py`, `backend/gigaam_asr.py`, `backend/diarize.py` — распознавание и спикеры; `backend/analyze.py` — работа с LLM; `backend/store.py` и `backend/backup.py` — хранение и резервное копирование.

### Где обрабатываются данные

**Self-hosted не означает полностью автономный или офлайн-режим.** Записи, транскрипты и результаты хранятся локально в `data/` (SQLite и файлы). При выборе **облачного ASR** аудио передаётся соответствующему провайдеру, а при использовании **облачной LLM** — транскрипт и контекст запроса. Для чувствительных записей выбирайте локальный ASR и внутренний LLM API, убедившись в допустимости обработки данных в вашем контуре. Веса локальных моделей могут скачиваться при первом запуске; для изолированной сети их нужно подготовить заранее.

## Системные требования

Минимум для развёртывания с моделью Whisper `small` (значение по умолчанию):

| Ресурс | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu 22.04/24.04 (Debian 12), x86_64 | то же, 4 vCPU |
| CPU | 2 ядра | 4 ядра |
| RAM | 4 ГБ | 8 ГБ |
| Свободное место | 8 ГБ | 20 ГБ и больше под записи и модели |
| Сеть | исходящий HTTPS при установке и для Qwen/OpenAI | без входящего 8000 из интернета |
| GPU | не нужен | — |

ПО, которое ставит `install.sh` или должно быть заранее: **Python 3.10+**, **ffmpeg** и **ffprobe**, **Node.js 18+** (только чтобы собрать интерфейс), компилятор (`build-essential`), git.

На 4 ГБ RAM не ставьте `LOCAL_WHISPER_SIZE=medium` или `large-*` — не хватит памяти. Архитектура ARM64 (Raspberry, Ampere) обычно работает, но колёса faster-whisper могут собираться дольше.

Для доступа с браузера достаточно обычного Chrome/Firefox/Safari. Порт по умолчанию **8000**.

## Установка на Linux без Docker

Нужен исходящий доступ в интернет при установке (пакеты, npm, PyTorch, модель Whisper ~500 МБ).

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/Alesnyt/MoM.git
cd MoM
chmod +x install.sh start.sh update.sh
./install.sh
./start.sh
```

`install.sh` ставит Python 3.10+, ffmpeg, компилятор, Node.js 18+, зависимости Python, собирает UI и скачивает Whisper `small` в `data/whisper/`.

Полезные флаги:

```bash
./install.sh --skip-model    # не качать Whisper сразу (скачается при первой расшифровке)
./install.sh --systemd       # установить и запустить сервис mom.service
```

Откройте `http://<IP-виртуальной-машины>:8000`. На первом входе администратора введите **SETUP_TOKEN** из вывода `install.sh` (он же в `.env`), создайте логин админа, сохраните API-ключ и заведите пользователей. Без профиля пользователя архив недоступен. Админка — отдельно: `http://<IP>/admin`.

## Установка через Docker

На хосте нужны Docker и Docker Compose. В рабочем образе уже есть Python, ffmpeg, PyTorch и зависимости ASR; frontend предварительно собирается в отдельном Node.js-слое. Веса моделей скачиваются отдельно. Модели и записи лежат в `./data`, настройки — в `./.env`.

```bash
cp .env.example .env
docker compose up -d --build
```

Первый запуск долгий: образ тянет CPU-сборку PyTorch. В логе будет `SETUP_TOKEN`, если в `.env` он пустой. Контейнер считается живым, когда `/api/health` отвечает.

Разметка спикеров в образ по умолчанию не входит. Чтобы поставить pyannote сразу:

```bash
docker compose build --build-arg INSTALL_DIARIZE=1
docker compose up -d
docker compose logs mom
```

Откройте `http://<IP>:8000`. Каталог `data/` и файл `.env` переживают пересборку контейнера. Сервер внутри контейнера работает от пользователя `mom`, не от root. Whisper `small` скачается в `data/whisper/` при первой расшифровке, не при сборке образа.

Образ публикуется в GHCR по тегам `v*` (или вручную через workflow): `ghcr.io/alesnyt/mom:latest`. **Слияние изменений в `main` само по себе не обновляет образ `:latest` в GHCR.** Для сборки проверенного кода на месте используйте `git pull --ff-only && docker compose up -d --build`; для установки опубликованного образа — `docker compose pull && docker compose up -d` (после проверки версии тега).

### Контур, где наружу ходит только GitHub

`docker compose build` на целевой машине снова тянет Docker Hub, PyPI, npm и Hugging Face. Если эти адреса закрыты, образ и веса собирают там, где они открыты (или в GitHub Actions), и привозят файлами.

На машине с доступом к этим адресам:

```bash
docker compose build
docker compose up -d
docker compose exec mom python -c "from faster_whisper import WhisperModel; WhisperModel('small', device='cpu', compute_type='int8', download_root='/app/data/whisper')"
docker compose down
docker save "$(docker compose images -q mom)" -o mom-image.tar
tar czf mom-models.tgz data/whisper data/hf
```

Если в админке выбран GigaAM, на той же машине заранее скачайте веса в `data/hf`. Код модели уже в репозитории, с Hugging Face берутся только `config.json` и `pytorch_model.bin` зафиксированных коммитов `ctc` и `large_ctc`. Иначе первая расшифровка снова пойдёт за весами.

В контуре:

```bash
git clone https://github.com/Alesnyt/MoM.git
cd MoM
cp .env.example .env
docker load -i mom-image.tar
tar xzf mom-models.tgz
```

В `.env` добавьте `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Запуск без повторной сборки: `docker compose up -d` (без `--build`). Облачный чат Qwen или OpenAI по-прежнему нужен исходящий HTTPS.

Не публикуйте порт 8000 в интернет. Для доступа снаружи поставьте Caddy или nginx с TLS — cookie `Secure` ставится только за HTTPS (или если запрос пришёл с localhost через доверенный прокси).

```Caddyfile
mom.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Пример nginx: терминация TLS на 443, `proxy_set_header X-Forwarded-Proto $scheme;` и `X-Forwarded-For`, а uvicorn слушает только `127.0.0.1:8000` (`HOST=127.0.0.1` в `.env`). Заголовки прокси MoM принимает только с loopback, иначе клиент не сможет сам объявить HTTPS.

## Переменные окружения

Файл `.env` не коммитится. Образец — `.env.example`. Значения читаются буквально: подстановка `${VARIABLE}` отключена, чтобы пароли со знаком `$` сохранялись без изменений. Настройки из админки записываются с экранированием.

Для уже установленного сервера задайте `MAX_UPLOAD_MB=2048` в его `.env` и
перезапустите приложение: `sudo systemctl restart mom` или `docker compose restart mom`.
Обновление сохраняет существующие значения `.env`, поэтому прежний лимит сам не повысится.
Интерфейс получает действующий лимит сервера, показывает его в форме и блокирует
слишком большой файл сразу при выборе или перетаскивании, до отправки записи.
Если перед приложением стоит прокси с собственным ограничением тела запроса,
его лимит должен вмещать файл 2 ГБ и служебные поля multipart.

| Переменная | Смысл |
|---|---|
| `HOST` | По умолчанию `0.0.0.0` (доступ с других машин) |
| `PORT` | По умолчанию `8000` |
| `SETUP_TOKEN` | Токен первого создания администратора (`install.sh` генерирует сам) |
| `OPENAI_API_KEY` | Ключ Qwen (`sk-sp-…` / `sk-ws-…`), OpenAI, Gemini (`AIza…` / `AQ.…`) или OpenRouter (`sk-or-…`); для своего API — выданный им ключ |
| `OPENAI_BASE_URL` | Базовый адрес OpenAI-совместимого API (в том числе локального) |
| `OPENAI_MODEL` | Идентификатор модели, которая формирует протокол |
| `WHISPER_MODEL` | `local-whisper` / `local-whisper-medium` или `gigaam-multilingual` / `gigaam-multilingual-large` |
| `LOCAL_WHISPER_SIZE` | `tiny` / `base` / `small` (по умолчанию) / `medium` / `large-v2` / `large-v3` |
| `WHISPER_CPU_THREADS` | Потоки вычислений Whisper. `0` — прежний выбор до 8 потоков; положительное число — явная настройка, ограниченная доступными CPU |
| `TORCH_CPU_THREADS` | Общая настройка вычислительных потоков PyTorch для GigaAM и Pyannote. `0` — оставить настройки PyTorch/окружения |
| `MAX_UPLOAD_MB` | Лимит загрузки записи, по умолчанию 2048 (2 ГБ) |
| `MIN_FREE_MB` | Не принимать запись, если свободно меньше этого запаса. По умолчанию `2048` |
| `UI_THEME` | Тема интерфейса: `classic` (по умолчанию) или `t2` |
| `MAX_JOBS` | Сколько встреч обрабатывать сразу: `1`–`8`, по умолчанию `1`. ffmpeg и Qwen идут параллельно; локальный Whisper/GigaAM в RAM один |
| `SMTP_HOST` | SMTP-сервер для писем «протокол готов» на email пользователя |
| `SMTP_PORT` | Обычно `587` (STARTTLS) или `465` (SSL) |
| `SMTP_USER` / `SMTP_PASSWORD` | Учётная запись SMTP |
| `SMTP_FROM` | Адрес отправителя |
| `SMTP_STARTTLS` | `1` по умолчанию; для порта 465 не нужен |
| `PUBLIC_BASE_URL` | Необязательная ссылка на MoM в письме, например `https://mom.company.ru` |
| `ASR_IDLE_UNLOAD_SECONDS` | Через сколько секунд простоя очереди выгрузить Whisper/GigaAM из RAM, по умолчанию `300` |
| `HF_TOKEN` | Токен Hugging Face для разметки спикеров (pyannote). Без него все реплики — один спикер |
| `DIARIZE_MAX_SPEAKERS` | Верхняя граница числа спикеров, по умолчанию `8` |
| `LDAP_ENABLED` | `1`, чтобы выбранные пользователи входили паролем из каталога |
| `LDAP_URL` | `ldaps://ldap.example.com:636` или `ldap://ldap.example.com:389` |
| `LDAP_BIND_DN` / `LDAP_BIND_PASSWORD` | Служебная учётная запись для поиска |
| `LDAP_BASE_DN` | База поиска, например `ou=people,dc=example,dc=com` |
| `LDAP_USER_FILTER` | Фильтр с `{username}`, по умолчанию `(mail={username})` |
| `LDAP_STARTTLS` | `1` для STARTTLS на `ldap://` |
| `LDAP_TLS_VERIFY` | `1` проверять сертификат, `0` принять самоподписанный (менее безопасно) |
| `LDAP_EMAIL_ATTR` | Атрибут email пользователя LDAP, по умолчанию `mail` |

Ключ можно задать и в веб-интерфейсе администратора.

## Производительность на CPU и замеры

Для локального Whisper/GigaAM исходная запись сразу преобразуется в один WAV
16 кГц, моно, PCM16. Этот же файл используется для распознавания и разметки
спикеров. GigaAM открывает WAV один раз на проход и передаёт короткие фрагменты
в модель из памяти, без временных файлов реплик и повторного декодирования ffmpeg.
В память читается только текущий фрагмент, а не вся многочасовая запись.
Общий WAV удаляется после обработки, ошибки или остановки; исходник сохраняется.
Для облачного ASR сохраняется прежняя отправка MP3.

Число потоков настраивается в `.env`, затем требуется перезапуск приложения.
Например, для проверки 12 потоков на сервере с достаточным числом выделенных CPU:

```env
WHISPER_CPU_THREADS=12
TORCH_CPU_THREADS=12
```

Это настройки потоков внутри модели, а не количества встреч в очереди.
GigaAM и Pyannote используют общую настройку PyTorch, потому что она действует
на процесс. Их выполнение по-прежнему защищено общим слотом локальных моделей.
Whisper использует отдельный движок. Значения `0` сохраняют прежние настройки;
отрицательные и некорректные значения также дают `0`. Явные значения ограничиваются
числом CPU, доступных процессу через affinity (при отсутствии API — числом CPU,
которое сообщает Python). Дробные квоты CPU контейнера автоматически не определяются:
для них задавайте значение в соответствии с выделенными ресурсами.

В журнале сервиса для каждой встречи появляются строки `timing` с её ID:

```text
INFO mom.performance [meeting-id] timing stage=audio_prepare seconds=2.125 outcome=ok
INFO mom.performance [meeting-id] timing stage=local_slot_wait seconds=0.010 outcome=ok
INFO mom.performance [meeting-id] timing stage=asr seconds=35.450 outcome=ok
INFO mom.performance [meeting-id] timing stage=diarization seconds=22.100 outcome=ok
INFO mom.pipeline [meeting-id] timing stage=total seconds=60.200 status=review audio_seconds=600.0
```

Это пример формата, а не результаты измерения. `audio_prepare` — подготовка аудио;
`local_slot_wait` — ожидание общей блокировки после запуска задания; `asr` — локальное
распознавание; `asr_cloud` — облачное распознавание, включая нарезку и запросы;
`diarization` — разметка спикеров; `protocol` — сборка протокола.
Отдельно замеряется загрузка моделей: `whisper_model_load`, `gigaam_model_load`,
`diarization_model_load`. Время загрузки уже входит во время соответствующего этапа,
поэтому эти значения нельзя суммировать повторно. `outcome=interrupted` означает
исключение или отмену этапа; итоговый статус встречи указан в строке `total`.
Время `total` начинается с запуска обработки и не включает ожидание задания
в общей очереди. Сборка протокола после проверки спикеров — отдельный запуск.

Для сравнения используйте одну и ту же запись, модель и настройки спикеров,
меняя только число потоков. Сравнивайте отдельно первый запуск с загрузкой модели
и последующие; выполните несколько повторов. Проверьте время `asr`, `diarization`,
общую длительность, RAM и качество текста/разметки. Само увеличение числа потоков
не гарантирует ускорения.

## Запуск после установки

```bash
./start.sh
```

Если порт занят: остановите другой процесс или `MOM_KILL_PORT=1 ./start.sh`.

Не запускайте несколько worker-процессов uvicorn: модель Whisper/GigaAM живёт в памяти одного процесса. Внутри процесса очередь (`MAX_JOBS`, по умолчанию 1) запускает несколько встреч сразу, если задать больше: вырезание аудио и запросы к Qwen параллелятся, локальное распознавание берёт модель по очереди, чтобы не грузить GigaAM дважды. После рестарта встреча с уже сохранённой расшифровкой продолжает только сборку протокола, а не гоняет Whisper заново. Сессии сохраняются в SQLite.

## Обновление с GitHub

**Для уже работающей установки:** сначала дождитесь завершения текущих задач, сохраните предыдущий коммит и сделайте резервную копию через `python -m backend.backup`. Не удаляйте `.env`, `data/` и Docker-тома. Пошаговая процедура для Docker/systemd, smoke-тесты и откат описаны в **[инструкции ручного обновления](docs/manual-upgrade-stage1.md)**.

После правок в репозитории на уже установленной ВМ без Docker:

```bash
cd MoM
git pull
chmod +x update.sh
./update.sh
```

Дальше достаточно `./update.sh`: он делает `git pull`, ставит Python-зависимости, пересобирает интерфейс и перезапускает `mom.service`, если сервис установлен. Файл `.env`, база и записи не трогаются. Новые переменные из `.env.example` дописываются, уже заданные значения не перезаписываются.

Если процесс запущен через `./start.sh`, после обновления остановите его и запустите снова.

Изменения первого этапа стабилизации объединены в [PR #1](https://github.com/Alesnyt/MoM/pull/1) (19 октября 2026): исправлен маршрут загрузки записи и чёрный экран интерфейса, усилена остановка и повторная обработка, локальные операции с моделями сериализованы, добавлены интеграционные и регрессионные тесты.

В [GitHub Actions](https://github.com/Alesnyt/MoM/actions/workflows/check.yml) проверяются Python-тесты, сборка React/TypeScript, Docker build и HTTP smoke-тест запущенного контейнера. На момент первого этапа: **67 автоматизированных Python-тестов**. Реальные длинные записи, качество ASR/LLM и работа с корпоративными LDAP/SMTP требуют отдельных испытаний в целевой среде.

```bash
python -m pytest -q
cd frontend && npm ci && npm run build
```

Обработка останавливается **кооперативно**: если локальная модель уже выполняет длительное вычисление, слот освобождается после завершения текущего шага, а результат остановленной задачи не должен публиковаться.

## Разработка на своей машине

Нужны Python 3.10+, Node.js 18+ и ffmpeg.

```bash
./install.sh --skip-model
./start.sh
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

## Как это работает

1. Запись помещается в очередь, `ffmpeg` извлекает аудио для распознавания.
2. Выбранный ASR обрабатывает речь: локальный Whisper (faster-whisper на CPU), Сбер GigaAM или совместимый облачный сервис.
3. Если задан `HF_TOKEN` и установлена опциональная зависимость `requirements-diarize.txt`, pyannote определяет говорящих. Без неё все реплики относятся к одному спикеру.
4. Встреча переходит в состояние `review`: можно переименовать спикеров и переназначить реплики или продолжить без ручной правки.
5. В блоке «Кому ещё отправить протокол» можно отметить спикеров: email подставляется при выборе имени из каталога или вводится вручную. Выбор получателей сохраняется вместе с командой «Собрать протокол», после которой выбранная LLM проверяет имена по разметке спикеров (если проверка включена), затем формирует саммари, решения, поручения и Minutes of Meeting.
6. Готовый результат доступен в архиве и в Markdown. Можно открыть черновик письма; при настроенном SMTP протокол автоматически отправляется владельцу записи и отмеченным спикерам отдельными письмами. Одинаковые адреса получают одно письмо. Смена или сброс имени спикера очищает прежний email и выбор получателя.

Несколько человек могут загрузить записи сразу: сервер ставит их в FIFO-очередь. Сколько идёт сразу, задаёт `MAX_JOBS` (1–8). По умолчанию один слот — безопасно для 4–8 ГБ. Если RAM и CPU позволяют, в админке поднимаете параллельность: ffmpeg и Qwen не ждут друг друга, локальный ASR не клонирует модель. В интерфейсе видно, сколько встреч впереди. Повтор после ошибки встаёт в конец очереди. SMTP задаётся в админке; без него обработка не падает — протокол просто остаётся в MoM.

## Данные

Локально в `data/`: SQLite (пользователи, протоколы, сессии), загрузки, аудио, кэш Whisper и Hugging Face (веса GigaAM). Каталог и `.env` в git не попадают и при `./update.sh` не удаляются.

Снимок базы и записей, без кэша моделей:

```bash
.venv/bin/python -m backend.backup
.venv/bin/python -m backend.backup --check backups/20261009T120000Z
```

В контейнере то же самое: `docker compose exec mom python -m backend.backup`. Каталог `./backups` смонтирован в контейнер. Команда пишет согласованную копию SQLite через `backup()`, плюс `uploads/`, `audio/` и `exports/`. Каталог снимка закрыт от остальных пользователей машины. Сразу после записи она открывает снимок только на чтение и проверяет `integrity_check`. Живую базу копировать через `cp` не нужно: у SQLite включён WAL.

В админке на сводке видно, сколько свободно на диске и сколько занимают записи. Если свободно меньше `MIN_FREE_MB` (по умолчанию 2 ГБ), новая загрузка не принимается.

## Сбер GigaAM Multilingual

По умолчанию стоит Whisper `small`. В админке можно выбрать **Whisper** (и размер) или **Сбер GigaAM Multilingual** 220M / 600M.

PyTorch и остальные пакеты GigaAM ставятся автоматически при `./install.sh` и `./update.sh`. Код модели лежит в репозитории (`backend/vendor/gigaam/modeling_gigaam.py`) и сверяется по SHA-256 перед импортом, поэтому процесс не исполняет скрипт, скачанный с Hugging Face. Веса по-прежнему качаются в `data/hf/` с зафиксированных коммитов, и размер файла сверяется. Если разметка спикеров включена, речь распознаётся один раз по границам голоса. Без неё длинная запись режется на куски по 24 с. На 4 ГБ RAM берите Whisper `tiny`/`small`, не GigaAM 600M.

### Готовая текстовая расшифровка

Встречу можно создать без аудио: вставить транскрипт со спикерами или загрузить `.txt`, `.md`, `.srt`, `.vtt`. Имена сохраняются, встреча сразу открывается на проверке спикеров; затем нажмите **«Собрать протокол»**. Распознавание речи, ffmpeg и диаризация для этого не нужны. [Форматы, API, лимиты и ручное обновление](docs/text-transcript-import.md).


### Проверка имён и системные промпты

После разметки спикеров, при запуске протокола, MoM отдельно проверяет упоминания имён через настроенную LLM. Передаются имена участников и реплики с авторами; адреса получателей в этот запрос не включаются. По умолчанию проверка включена. Если остались только автоматические имена («Спикер 1»), сопоставление пропускается.

Модель различает ошибку в имени участника, корректное имя, упоминание другого человека и неоднозначный случай. Инструкция требует явной контекстной связи с участником; сходства звучания недостаточно. Например, первое «Оля» в обращении может стать «Аля», а второе «Оля из бухгалтерии» в той же реплике останется. Корректные сокращения и падежи сохраняются. Это вероятностная проверка текста, а не повторное прослушивание аудио: решение модели всё ещё может оказаться неверным.

Применяются только адресные замены имён с точным совпадением исходного вхождения, известным участником, высокой уверенностью модели и объяснением. Противоречивые предложения не применяются. Исходные реплики сохраняются в `original_text`, отчёт — в `name_review` внутри `segments_json`; во вкладке «Транскрипт» доступны объяснения и текст до исправления. Таймкоды, авторы реплик и получатели письма не меняются. Саммари и протокол строятся по исправленному тексту. При сбое проверки весь проход отменяется, протокол строится по исходному тексту, а интерфейс показывает сообщение о сбое.

Длинные транскрипты проверяются частями с соседними репликами для контекста; длинные импортированные реплики делятся только внутри запроса, их сохранённая разметка не меняется. Повторный запуск использует готовую проверку, если текст, разметка, модель и инструкция не изменились. При изменении этих данных проверка начинается с сохранённого исходного текста. Отключение проверки и повторная сборка также возвращают исходные имена.

В **Администрирование → Промпты** администратор видит и редактирует фактические системные промпты протокола и проверки имён, включает или отключает проверку, возвращает стандартный текст. После подстановки стандартного текста нужно нажать «Сохранить». JSON-схемы в инструкциях нужны приложению для разбора ответа. Изменения действуют при следующих запусках; готовые встречи не пересчитываются автоматически. Все части одного протокола используют один снимок инструкции.

Настройки сохраняются версиями в таблице `llm_settings` SQLite и входят в резервную копию базы; редактирование отмечается в журнале администратора. API `GET/POST /api/settings/prompts` доступно только администратору. Проверка имён добавляет LLM-запросы и время обработки; её качество следует оценить на реальных примерах конкретного провайдера.


### Ограничение поиска людей в AD / LDAP

В **Администрирование → Каталог → Области поиска людей** доступны два режима: вся настроенная база (исходное поведение) или только выбранные области. Кнопка «Загрузить домены и OU» читает метаданные RootDSE, затем позволяет открывать подразделения по одному уровню, с постраничной загрузкой. Список сотрудников при просмотре структуры не выгружается. Показываются только области, доступные через настроенный сервер и служебную учётную запись; это не обещание обнаружить все домены леса. Нужный DN можно добавить вручную.

Отметьте необходимые OU или домены и нажмите «Сохранить области поиска». Выбор включает **всё поддерево**: если подрядчики лежат внутри общего родительского OU, выберите отдельные дочерние OU сотрудников. В режиме выбранных областей пустой список отключает AD-подсказки. Ошибка DN, отсутствие доступа или смена сервера/базы не приводят к поиску по всему AD. После смены подключения ранее ограниченный поиск приостанавливается до проверки и повторного сохранения областей. Ограничения сохраняются в SQLite (`app_settings`, ключ `ldap_people_scope`) и входят в резервную копию базы.

Ограничение применяется к AD-подсказкам спикеров и подбору каталожных пользователей в админке. Уже созданные локальные профили MoM остаются в подсказках. **Вход через LDAP** продолжает использовать собственную базу и фильтр пользователя: область поиска имён не меняет доступ действующих пользователей. Поиск людей использует только объекты person, исключает компьютеры, не следует LDAP referrals/aliases, объединяет результаты нескольких областей без повторов и ограничивает количество ответов. При просмотре дерева и поиске действуют ограничения времени ответа; при необходимости выбирайте более узкие OU.

Список имён отменяет предыдущий запрос при продолжении ввода и игнорирует его поздний ответ, включая позднюю ошибку. Переход фокуса внутри редактора не запускает автосохранение. Выбрать подсказку можно мышью или стрелками и Enter; Escape отменяет ввод. При выходе из всего редактора ручное имя сохраняется, как и по кнопке «Сохранить». Пока идёт запрос, показывается индикатор поиска.

Проверки: `pytest` покрывает сохранение областей, пустой список, смену подключения, точные базы LDAP-запросов, исключение вложенных повторов, ошибки областей, неизменность поиска при входе, постраничный просмотр структуры и доступ только администратора. В браузере проверены ответы запросов в обратном порядке, выбор мышью/клавиатурой, переход фокуса к сбросу и сохранение выбранного OU на тестовом каталоге. Проверку связи с рабочим AD нужно выполнять в контуре установки.

Корпоративное развёртывание с nginx, TLS, прокси, корпоративными CA и областями входа AD описано в [отдельной инструкции](deploy/corporate/README.md).
